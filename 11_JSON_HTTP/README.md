# Лабораторная работа № 11. JSON и получение данных по HTTP

## Цель работы

Научиться читать и записывать данные в формате JSON, проверять их структуру, обрабатывать исключения, анализировать
данные и получать информацию по HTTP.

## 1. Подготовка учебного набора данных — `todos.json`

Назначение: создание JSON-файла, содержащего список задач пользователей.

Каждая задача содержит следующие поля:

- `id` — идентификатор задачи;
- `userId` — идентификатор пользователя;
- `title` — название задачи;
- `completed` — статус выполнения задачи.

## 2. Проверка и анализ данных — `analysis.py`

Назначение: проверка корректности структуры данных, подсчёт выполненных задач и определение пользователей-лидеров.

Реализованные функции:

- `validate_todos(data)` — проверка структуры данных;
- `completion_counts(todos)` — подсчёт выполненных задач каждого пользователя;
- `top_users(counts)` — определение пользователей с максимальным количеством выполненных задач.

### Проверка подсчёта задач и определения лидеров

| Тип проверки | Входные данные          | Ожидаемый результат | Фактический результат |
|--------------|-------------------------|---------------------|-----------------------|
| Обычная      | Учебный набор задач     | `{5: 2, 10: 2}`     | `{5: 2, 10: 2}`       |
| Граничная    | Пустой список задач     | `{}`                | `{}`                  |
| Особая       | Все задачи не завершены | `{5: 0, 10: 0}`     | `{5: 0, 10: 0}`       |
| Обычная      | `{5: 3, 10: 1}`         | `[5]`               | `[5]`                 |
| Особая       | `{10: 2, 5: 2}`         | `[5, 10]`           | `[5, 10]`             |
| Граничная    | `{}`                    | `[]`                | `[]`                  |
| Особая       | `{5: 0, 10: 0}`         | `[]`                | `[]`                  |

### Проверка структуры данных

| Тип проверки | Входные данные          | Ожидаемый результат | Фактический результат |
|--------------|-------------------------|---------------------|-----------------------|
| Обычная      | Корректный список задач | Проверка пройдена   | Проверка пройдена     |
| Особая       | Словарь вместо списка   | `ValueError`        | Не подтверждено       |
| Особая       | Повторяющийся `id`      | `ValueError`        | Не подтверждено       |
| Особая       | Отсутствует `userId`    | `ValueError`        | Не подтверждено       |
| Особая       | `completed = "false"`   | `ValueError`        | Не подтверждено       |
| Особая       | `id = True`             | `ValueError`        | Не подтверждено       |

## 3. Чтение и сохранение результатов — `main.py`

Назначение: чтение данных из файла `todos.json`, проверка их корректности, подсчёт выполненных задач, определение
лидеров и сохранение их завершённых задач в файл `leaders.json`.

В программе предусмотрена обработка исключений:

- `FileNotFoundError`;
- `UnicodeError`;
- `json.JSONDecodeError`;
- `ValueError`;
- `OSError`.

| Тип проверки | Входные данные                               | Ожидаемый результат                | Фактический результат            |
|--------------|----------------------------------------------|------------------------------------|----------------------------------|
| Обычная      | Корректный файл `todos.json`                 | Лидеры: `[5, 10]`                  | Лидеры: `[5, 10]`                |
| Обычная      | Учебный набор задач                          | Сохранение задач с ID 1, 3, 4, 5   | Не подтверждено содержимое файла |
| Особая       | Некорректный JSON                            | Сообщение об ошибке                | Не подтверждено                  |
| Особая       | Некорректный JSON при наличии `leaders.json` | Предыдущий результат не изменяется | Не подтверждено                  |

## 4. Индивидуальное задание (вариант № 2) — `analysis.py`, `main.py`

Назначение: отбор завершённых задач пользователя по введённому идентификатору и сохранение результата в файл
`selected.json` с сохранением исходного порядка задач.

Реализованные функции:

- `select_tasks(todos, user_id, parameter=None)` — отбор завершённых задач указанного пользователя;
- `read_user_id()` — ввод положительного целого идентификатора пользователя с повторным запросом при ошибке.

| Тип проверки | Входные данные                       | Ожидаемый результат | Фактический результат |
|--------------|--------------------------------------|---------------------|-----------------------|
| Обычная      | `user_id = 5`                        | Задачи с ID 1 и 5   | Задачи с ID 1 и 5     |
| Обычная      | `user_id = 10`                       | Задачи с ID 3 и 4   | Не подтверждено       |
| Граничная    | `user_id = 99`                       | `[]`                | Не подтверждено       |
| Граничная    | Пустой список задач                  | `[]`                | `[]`                  |
| Особая       | У пользователя нет завершённых задач | `[]`                | `[]`                  |
| Особая       | Ввод `0`                             | Повторный ввод      | Не подтверждено       |
| Особая       | Ввод `-5`                            | Повторный ввод      | Не подтверждено       |
| Особая       | Ввод `abc`                           | Повторный ввод      | Не подтверждено       |
| Особая       | Ввод `2.5`                           | Повторный ввод      | Не подтверждено       |

## 5. Получение данных по HTTP — `fetch_profile.py`

Назначение: получение информации о пользователе GitHub с помощью HTTP-запроса к GitHub API и сохранение полученных
данных в файл `profile.json`.

Для выполнения HTTP-запроса используется стандартная библиотека `urllib`.

Реализованные функции:

- `fetch_profile(login)` — формирование и отправка HTTP-запроса, получение и проверка данных;
- `main()` — ввод логина, сохранение профиля и обработка исключений.

При отправке запроса используются заголовки `Accept` и `User-Agent`, а также таймаут сетевых операций в 10 секунд.

| Тип проверки | Входные данные                | Ожидаемый результат            | Фактический результат |
|--------------|-------------------------------|--------------------------------|-----------------------|
| Обычная      | `octocat`                     | Получение и сохранение профиля | Профиль сохранён      |
| Граничная    | Пустой логин                  | Сообщение об ошибке            | Не подтверждено       |
| Особая       | Несуществующий пользователь   | Обработка ошибки HTTP          | Не подтверждено       |
| Особая       | Отсутствие подключения к сети | Обработка сетевой ошибки       | Не подтверждено       |

## 6. Автоматическое тестирование — `test_analysis.py`

Назначение: автоматическая проверка корректности работы функций с помощью оператора `assert`.

Выполнены проверки:

- подсчёта выполненных задач;
- определения одного и нескольких лидеров;
- обработки пустого списка;
- обработки набора без завершённых задач;
- отбора задач конкретного пользователя;
- обнаружения некорректных данных;
- записи и повторного чтения JSON-файла.

Для проверки записи и чтения JSON используется временная папка, создаваемая с помощью `TemporaryDirectory()`.

| Тип проверки                   | Ожидаемый результат                         | Фактический результат     |
|--------------------------------|---------------------------------------------|---------------------------|
| Анализ учебного набора         | Все проверки пройдены                       | Все проверки пройдены     |
| Граничные случаи               | Все проверки пройдены                       | Все проверки пройдены     |
| Индивидуальный вариант         | Все проверки пройдены                       | Не подтверждено полностью |
| Некорректные данные            | Возникновение `ValueError`                  | Не подтверждено           |
| Запись и повторное чтение JSON | Исходные и восстановленные данные совпадают | Не подтверждено           |
